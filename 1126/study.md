# 📚 어셈블리 및 컴퓨터 구조 핵심 학습 노트

오늘 학습한 기호와 인지 한계, 컴퓨터의 역사와 양자컴퓨터, 데이터 표현, 프로그램 실행 과정과 메모리 구조, CPU 레지스터, 조건문(`IF` = `CMP` + `JUMP`), 스택의 기초부터 스택 프레임과 재귀, 그리고 C언어 인라인 어셈블리(MASM)의 핵심 내용을 정리한 요약서입니다.

---

## 1. 인간의 기호 인지 한계와 어셈블리어의 탄생

* **작업 기억의 한계 (코완의 법칙):** 인간이 보조 수단 없이 머릿속으로 실수 없이 다룰 수 있는 기호의 개수는 평균 4개(±1개)입니다.
* **`0`과 `1`(이진수) 반복 시 오류 발생 시점:**
  * 무작위 이진수 나열을 기억할 때는 **7~9자리**를 넘어가면 순서를 헷갈립니다.
  * 연속된 같은 숫자(`0000010000`)를 눈으로 셀 때는 **4~5개**를 넘어가면 시각적 군집 착각으로 자리수를 놓칩니다.
* **어셈블리어의 탄생 배경:** 인간이 `0`과 `1`의 나열(기계어)을 실수 없이 다루는 것이 불가능했기 때문에, 이를 인간이 읽기 쉬운 영어 단어(니모닉: `MOV`, `ADD` 등)로 1:1 대응시킨 것이 바로 **어셈블리어**입니다.

## 2. 컴퓨터의 나이 & 양자컴퓨터 (2026년 기준)

### ① 기존 컴퓨터(고전 컴퓨터)의 나이
* **현대 전자식 디지털 컴퓨터 (약 80세):** 최초의 범용 전자식 컴퓨터 **에니악(ENIAC, 1946년)** 기준.
* **프로그램 내장형 컴퓨터 (약 77세):** 현대 컴퓨터 구조(폰 노이만 구조)를 처음 구현한 **에드삭(EDSAC, 1949년)** 기준.

### ② 양자컴퓨터 (Quantum Computer)
* **나이:** 이론 제안(1981년) 기준 약 45세, 최초 물리 구현(1998년) 기준 약 28세로, 현재 상용화 초기 단계에 들어선 **성장기 기술**입니다.
* **핵심 차이 (비트 vs 큐비트):**

| 구분 | 기존 컴퓨터 (고전 컴퓨터) | 양자컴퓨터 (Quantum Computer) |
| :--- | :--- | :--- |
| **정보 단위** | **비트 (Bit)** | **큐비트 (Qubit)** |
| **상태 표현** | `0` **또는** `1` 중 하나만 가능 | `0`과 `1`이 동시에 중첩(Superposition)됨 |
| **연산 방식** | 한 번에 하나씩 순차 계산 | 모든 경우의 수를 동시에 병렬 계산 |
| **역할 분담** | 일반 연산, 문서, 게임, 시스템 제어 | 암호 해독, 신약 개발, 초거대 최적화 연산 (보조 프로세서 역할) |

## 3. 데이터 표현: 숫자 `1` vs 문자 `'1'`

컴퓨터에서 **문자는 입출력(사람과의 소통)을 담당**하고, **숫자는 내부 계산을 담당**하므로 완전히 다른 값으로 저장됩니다.

| 구분 | 숫자 `1` (정수, Integer) | 문자 `'1'` (아스키 코드, ASCII) |
| :--- | :--- | :--- |
| **코드 표기** | `1` (따옴표 없음) | `'1'` (따옴표 있음) |
| **실제 저장 값** | **`1`** (2진수 `0000 0001`) | **`49`** (아스키 코드표 49번, 2진수 `0011 0001`) |
| **주요 용도** | CPU 내부 산술 연산 (`+`, `-`, `*`, `/`) | 키보드 입력 및 모니터 화면 출력 |
| **`+ 1` 연산 시** | `1 + 1 = 2` (숫자 2) | `'1' + 1 = 50` $\rightarrow$ 화면 출력 시 문자 **`'2'`** |

## 4. 프로그램 실행 과정과 메모리 구조 (4대 영역)

### ① 프로그램이 실행될 때 거치는 과정 (하드디스크 $\rightarrow$ RAM $\rightarrow$ CPU)
1. **프로그램 실행 요청:** 사용자가 실행 파일(`.exe`)을 더블클릭하면 운영체제(OS)가 프로그램 실행을 준비합니다.
2. **메모리(RAM) 방 배정:** OS가 하드디스크에 있던 프로그램 파일을 메모리(RAM)로 불러오면서 용도에 맞게 **4개의 방(코드, 데이터, 힙, 스택)**으로 나누어 배치합니다.
   * 실행할 기계어 명령어들은 **코드(`.code`)** 방에 넣습니다.
   * 미리 선언한 변수와 배열 등은 **데이터(`.data`)** 방에 넣습니다.
3. **CPU 실행 시작:** OS가 코드 방의 첫 번째 명령어 주소를 CPU의 **`EIP` 레지스터**에 넣어주면, CPU가 한 줄씩 명령어를 꺼내 실행하면서 필요할 때마다 **스택(`Stack`)** 방을 임시 메모장으로 사용합니다.

### ② 메모리 4대 영역 구조도
```text
+-----------------------+  높은 주소 (High Address)
|      스택 (Stack)     |  <-- PUSH, POP, 지역변수, 복귀 주소 (아래로 자람 ↓)
+-----------------------+
|           ↓           |
|      (빈 공간)        |
|           ↑           |
+-----------------------+
|       힙 (Heap)       |  <-- 실행 중 동적 메모리 할당 공간 (위로 자람 ↑)
+-----------------------+
|     데이터 (Data)     |  <-- 어셈블리의 .data 영역 (전역변수, 구조체, 배열)
+-----------------------+
|      코드 (Code)      |  <-- 어셈블리의 .code 영역 (기계어 명령어, 읽기 전용)
+-----------------------+  낮은 주소 (Low Address)
```

## 5. x86 CPU 핵심 레지스터 16개

### ① 범용 레지스터 (8개, 32비트) — 연산 및 주소 처리
* **`EAX` (Accumulator):** 산술 연산의 중심 및 함수 **반환값(Return Value)** 저장 (`AX` $\rightarrow$ `AH`/`AL`로 쪼개 사용 가능)
* **`EBX` (Base):** 메모리 기준 주소 지정 및 일반 데이터 보관
* **`ECX` (Counter):** `LOOP` 명령어 등 반복문의 **반복 횟수 카운터**
* **`EDX` (Data):** 큰 수의 곱셈/나눗셈 보조 및 입출력(I/O) 데이터 처리
* **`ESI` (Source Index):** 문자열/배열 복사 시 **원본(출발지)** 주소 포인터
* **`EDI` (Destination Index):** 문자열/배열 복사 시 **대상(목적지)** 주소 포인터
* **`ESP` (Stack Pointer):** 현재 **스택의 맨 꼭대기(Top)** 주소를 실시간으로 가리킴
* **`EBP` (Base Pointer):** 함수 호출 시 **스택 프레임의 고정 기준점** 역할

### ② 세그먼트 레지스터 (6개, 16비트) — 메모리 구역 지정
* **`CS`** (코드 구역), **`DS`** (데이터 구역), **`SS`** (스택 구역), **`ES`** (추가 데이터 구역), **`FS` / `GS`** (OS 스레드 및 시스템 정보 구역)

### ③ 제어 및 상태 레지스터 (2개, 32비트)
* **`EIP` (Instruction Pointer):** **다음에 실행할 명령어의 주소**를 가리킴 (명령어 실행 시마다 자동 갱신)
* **`EFLAGS` (Flags):** 연산 직후의 상태 기록 (`ZF`: 결과가 0이면 1, `SF`: 음수면 1, `CF`: 자리올림 발생 시 1 등)

## 6. CPU 명령어 실행에 따른 레지스터 변화

* **데이터 이동 (`mov eax, 10`):** 오른쪽 값을 왼쪽으로 복사. **`EFLAGS`는 변하지 않으며**, `EIP`만 다음 명령어로 이동.
* **산술 연산 (`sub eax, 5`):** 계산 결과를 왼쪽 레지스터에 저장하고, 결과에 따라 **`EFLAGS`가 즉시 갱신**됨 (예: 결과가 `0`이면 `ZF = 1`).
* **스택 조작 (`push` / `pop`):** 스택은 아래(낮은 주소)로 자라므로 **`push` 시 `ESP`가 4 감소**, **`pop` 시 `ESP`가 4 증가**.
* **함수 호출 (`call` / `ret`):** `call`은 복귀 주소를 스택에 `push`(`ESP - 4`)하고 `EIP`를 함수 주소로 점프시키며, `ret`는 스택에서 복귀 주소를 꺼내 `EIP`에 복원(`ESP + 4`).

## 7. 어셈블리어 조건문: `IF` = `CMP` + `JUMP`

우리가 C언어나 파이썬에서 쓰는 **`IF`문은 기계어(어셈블리어) 차원에서 보면 결국 `CMP`(비교)와 `JUMP`(점프)를 합쳐놓은 것과 완전히 같습니다.** (MASM의 `.IF` 지시어 역시 컴파일되면 내부적으로 `CMP`와 `JUMP` 코드로 변환됩니다.)

1. **`CMP dest, src` (비교하기):** 내부적으로 `dest - src` 뺄셈을 수행하되 **두 변수의 원래 값은 바꾸지 않고 `EFLAGS`(상태 플래그)만 변경**합니다.
2. **`Jcc` (조건부 점프):** 방금 바뀐 `EFLAGS`를 확인하고 조건이 맞으면 해당 위치로 점프(`EIP` 변경)합니다.
   * 같을 때 / 다를 때: **`JE`** (Jump if Equal, `ZF=1`), **`JNE`** (Jump if Not Equal, `ZF=0`)
   * 부호 있는 수(`SDWORD`) 크기 비교: **`JG`** (크다), **`JL`** (작다)
   * 부호 없는 수(`DWORD`) 크기 비교: **`JA`** (크다), **`JB`** (작다)

```masm
; C언어의 if (eax == 10) { ebx = 1; } else { ebx = 2; } 는 아래와 완전히 같음
    cmp eax, 10         ; 1단계: 비교 (eax - 10 계산 -> 같으면 ZF = 1)
    jne ElseBlock       ; 2단계: 점프 (다르면 ElseBlock으로 이동)
    mov ebx, 1          ; 참일 때 실행
    jmp EndIf           ; else 구역 건너뛰기
ElseBlock:
    mov ebx, 2          ; 거짓일 때 실행
EndIf:
```

## 8. 스택(Stack)의 기초부터 스택 프레임과 재귀 호출까지

### ① 가장 쉬운 스택(Stack)의 개념: '접시 쌓기'
* **구조 (LIFO - Last In, First Out):** 식당에서 접시를 위로 차곡차곡 쌓아 올리면, 꺼낼 때는 **가장 나중에 올린 맨 위 접시부터 먼저 꺼내는 것**과 똑같은 구조입니다.
* **기본 동작 2가지:**
  * **`PUSH` (넣기):** 스택의 맨 꼭대기에 데이터를 하나 올려놓습니다.
  * **`POP` (꺼내기):** 스택의 맨 꼭대기에 있는 데이터를 하나 꺼내옵니다.
* **메모리 방향 특이점:** 실제 컴퓨터 메모리에서 스택은 **위(높은 주소)에서 아래(낮은 주소) 방향으로 거꾸로 자랍니다.** 그래서 데이터를 `PUSH`할수록 주소 포인터(`ESP`) 숫자는 줄어듭니다.

### ② 프로시저(함수)에 스택이 꼭 필요한 이유
1. **돌아갈 집 주소(복귀 주소) 기억:** 함수 A가 함수 B를 부를 때(`CALL`), B가 끝난 뒤 A의 어디로 돌아와야 할지 그 주소를 스택에 `PUSH`해 둡니다. 스택이 없으면 함수를 여러 개 거칠 때 돌아갈 주소를 잃어버립니다.
2. **임시 메모장 역할:** 레지스터 개수가 부족할 때 기존 값을 스택에 잠깐 `PUSH`해 두었다가, 작업이 끝나면 `POP`으로 원래 값을 안전하게 복원합니다.

### ③ 스택 프레임 (Stack Frame) — 함수별 독립된 방
* 프로시저가 다른 프로시저를 중첩(내포) 호출할 때, 서로의 데이터가 섞이지 않도록 **각 함수마다 스택 안에 할당받는 전용 작업 구역**(매개변수 + 복귀 주소 + 이전 `EBP` + 지역변수)을 말합니다.

### ④ 재귀 호출 (Recursive Call)과 스택
* **재귀 호출:** 프로시저가 작업 도중 **자기 자신을 다시 호출**하는 방식입니다.
* **스택이 필수인 이유:** `Factorial(3)` $\rightarrow$ `Factorial(2)` $\rightarrow$ `Factorial(1)` 순서로 자기 자신을 부를 때마다 **각 단계의 변수(`n=3`, `n=2`, `n=1`)가 별도의 스택 프레임에 각각 따로 저장**됩니다. 덕분에 `n=1`이 끝나고 되돌아올 때 이전 단계의 `n=2`와 `n=3` 값을 잃어버리지 않고 곱셈을 이어갈 수 있습니다.
* *(주의: 종료 조건을 잘못 설정해 무한히 호출하면 스택 공간이 꽉 차서 프로그램이 강제 종료되는 **스택 오버플로우(Stack Overflow)**가 발생합니다.)*

## 9. C언어 안에 MASM 인라인 어셈블리 넣기

Visual Studio(`x86` 32비트 환경)에서는 **`__asm`** 블록을 사용해 C 변수와 어셈블리 코드를 직접 결합할 수 있습니다.

```c
#include <stdio.h>

int GetMax(int x, int y) {
    __asm {
        mov eax, x          ; 첫 번째 인자 x를 EAX에 저장
        cmp eax, y          ; x와 y 비교
        jge Done            ; x >= y 이면 점프
        mov eax, y          ; y가 더 크면 y를 EAX에 덮어씀
    Done:
        ; 함수 종료 시 EAX에 담긴 값이 C언어의 return 값으로 자동 반환됨
    }
}

int main() {
    int maxVal = GetMax(45, 82);
    printf("더 큰 값: %d\n", maxVal); // 출력: 82
    return 0;
}
```
