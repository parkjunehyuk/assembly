# 💻 x86 어셈블리 핵심 명령어 실습 (Irvine32)

이 문서는 x86 어셈블리(MASM / Irvine32 환경)의 핵심 문자열 처리 명령어(`STOSD`, `SCASB`, `Str_compare`)와 16비트 나눗셈(`DIV`) 구조를 직관적으로 이해하기 위한 학습 가이드 및 전체 예제 코드입니다.

---

## 🧠 핵심 개념 한눈에 보기 (택배 기사님 비유)

어셈블리 명령어를 볼 때 **데이터가 CPU 안에 있는지, 메모리(RAM)에 있는지** 구분하는 것이 가장 중요합니다.

* **CPU** = 택배 기사님
* **`EAX` (A 레지스터 / Accumulator)** = 기사님 오른손에 들린 **실제 데이터 바구니**
  * 크기에 따라 이름만 달라집니다: `AL`(1바이트), `AX`(2바이트), `EAX`(4바이트)
* **`EDI` (Destination Index)** = 기사님 왼손에 들린 **배송지 주소 메모지** (값이 아니라 메모리 주소가 들어있음)
* **`[EDI]` (대괄호의 의미)** = *"EDI 메모지에 적힌 메모리 주소로 찾아가서, 그 방 문을 열어라!"*
* **메모리 (RAM)** = 실제 데이터가 저장되는 거대한 아파트 건물

---

## 📌 학습 포인트 요약

1. **`REP STOSD` (메모리 초기화)**
   * `EAX`에 담긴 값을 `[EDI]` 주소가 가리키는 메모리에 쓰고, `EDI` 주소를 자동으로 `+4`(4바이트)씩 이동시키며 `ECX`번 반복합니다.
2. **`REPNE SCASB` (문자열 탐색)**
   * `AL`에 담긴 1바이트 문자와 `[EDI]`의 문자를 비교하며 `EDI`를 `+1`씩 이동합니다.
   * 같은 문자를 찾으면 **Zero Flag(`ZF = 1`)**가 켜지며 즉시 멈추고, 끝까지 못 찾으면 `ZF = 0` 상태로 종료되어 `JNZ` 점프가 실행됩니다.
3. **`Str_compare` & `JC` (문자열 사전순 비교)**
   * 앞 문자열에서 뒤 문자열을 뺄 때(예: `'A'(65) - 'B'(66)`) 빌림(Borrow)이 발생하면 **Carry Flag(`CF = 1`)**가 켜집니다.
4. **`DX:AX` 16비트 나눗셈 (`DIV BX`)**
   * 16비트 나눗셈 시 피나눗수(분자)는 항상 `[DX : AX]` 쌍으로 결합해 사용하므로 나눗셈 전 `mov dx, 0` 초기화가 필수입니다.
   * 연산 후 **몫은 `AX`**, **나머지는 `DX`**에 자동으로 저장됩니다.

## 📜 전체 실습 코드 (`main.asm`)

```assembly
INCLUDE Irvine32.inc

; 콘솔 한글 깨짐 방지를 위한 Windows API 함수 불러오기
SetConsoleOutputCP PROTO, wCodePageID:DWORD

.data
    ; =========================================================================
    ; [데이터 영역] 프로그램이 사용할 변수(메모리 방)들을 미리 만들어 둡니다.
    ; =========================================================================
    
    ; 1. STOSD 연습용: 4바이트(DWORD)짜리 빈 방 5개 만들기
    ;    처음엔 쓰레기 값(?)이 들어있음 -> [ ? | ? | ? | ? | ? ]
    targetArray  DWORD 5 DUP(?)             
    
    ; 2. SCASB 연습용: 1바이트(BYTE)짜리 글자들이 나란히 들어있는 방
    ;    맨 끝의 0은 "문자열이 여기서 끝났다"는 표시(Null 종료 문자)
    sampleText   BYTE  "PASS-77-OK", 0      
    
    ; 3. Str_compare 연습용: 사전순 비교할 두 단어
    str1         BYTE  "Apple", 0           ; 'A'의 아스키 코드 = 65
    str2         BYTE  "Banana", 0          ; 'B'의 아스키 코드 = 66

    ; 4. 화면 출력용 안내 문구들
    msgFound     BYTE  "[1] SCASB 결과    : 문자 '7'을 찾았습니다!", 0
    msgNotFound  BYTE  "[1] SCASB 결과    : 문자를 찾지 못했습니다.", 0
    msgCompare   BYTE  "[2] Str_compare 결과: str1이 str2보다 사전순으로 앞섭니다 (CF=1).", 0
    msgDivResult BYTE  "[3] 16비트 DIV 결과 : 105 / 10 = 몫 ", 0
    msgRemainder BYTE  ", 나머지 ", 0

.code
main PROC
    ; [기본 세팅] 콘솔 창 출력을 UTF-8(65001)로 맞춰서 한글이 안 깨지게 함
    INVOKE SetConsoleOutputCP, 65001


    ; =========================================================================
    ; SECTION 1. STOSD (Store String Doubleword) : 메모리에 값 도장 찍듯 채우기
    ; =========================================================================
    ; 💡 핵심 원리: STOSD는 코드에 적지 않아도 무조건 'EAX의 값'을 '[EDI] 주소'에 넣습니다!
    
    cld                                  ; [방향 결정] Clear Direction Flag (DF = 0)
                                         ; -> "앞에서 뒤로(주소 증가 방향) 도장을 찍겠다!" 선언
                                         ; (만약 거꾸로 뒤에서 앞으로 가려면 STD를 씁니다)

    mov eax, 99                          ; [도장 잉크 준비] 메모리에 찍어 넣을 숫자 99를 EAX에 담음
                                         ; (주의! STOSD는 무조건 EAX만 쳐다봅니다. EBX에 넣으면 안 됨!)

    mov edi, OFFSET targetArray          ; [도장 찍을 첫 위치] targetArray의 맨 첫 번째 칸 주소를 EDI에 담음
                                         ; (OFFSET = 내용물이 아니라 '주소 표지판'을 가져오는 키워드)

    mov ecx, 5                           ; [반복 횟수] 도장을 몇 번 찍을지 ECX에 설정 (5칸이니까 5번)
    
    rep stosd                            ; ★ 마법의 한 줄! 아래 3가지 일을 ECX(5)번 자동으로 반복함:
                                         ;   ① EAX(99) 값을 EDI가 가리키는 메모리 칸에 집어넣음
                                         ;   ② D(Doubleword = 4바이트)이므로 EDI 주소를 자동으로 +4 증가시킴!
                                         ;   ③ ECX를 1 줄임 (5 -> 4 -> 3 -> 2 -> 1 -> 0이 되면 멈춤)
                                         ; 결과: targetArray = [ 99 | 99 | 99 | 99 | 99 ] 완성!


    ; =========================================================================
    ; SECTION 2. SCASB (Scan String Byte) : 문자열 속에서 '7' 찾아내기
    ; =========================================================================
    ; 💡 핵심 원리: SCASB는 코드에 안 써도 무조건 'AL의 글자'와 '[EDI]의 글자'를 비교합니다!

    cld                                  ; [방향 결정] 앞에서 뒤로 한 글자씩 읽으며 전진 (주소 +1씩 증가)

    mov al, '7'                          ; [찾을 목표물] 찾고 싶은 글자 '7'을 AL(1바이트)에 쥐여줌
                                         ; (주의! SCASB는 1바이트 비교라서 무조건 AL만 봅니다!)

    mov edi, OFFSET sampleText           ; [탐색 시작점] "PASS-77-OK"의 맨 첫 글자('P') 주소를 EDI에 담음

    mov ecx, LENGTHOF sampleText         ; [최대 탐색 한도] 문자열 전체 길이(11글자)만큼만 찾도록 설정
                                         ; (끝없이 메모리를 뒤지는 사고를 막기 위한 안전장치)

    repne scasb                          ; ★ 핵심 탐색 루프! (REPeat while Not Equal = 다르면 계속 반복)
                                         ; 한 바퀴 돌 때마다 내부에서 일어나는 일:
                                         ;   ① AL('7')과 [EDI]의 글자를 몰래 빼봄 (AL - [EDI])
                                         ;   ② 다음 글자를 검사하기 위해 EDI 주소를 자동으로 +1 증가시킴!
                                         ;   ③ ECX를 1 줄임
                                         ;   ④ 만약 두 글자가 같으면(빼기 결과 = 0) -> Zero Flag(ZF)가 1이 되면서 즉시 멈춤!
                                         ;   ⑤ 다르면(ZF = 0) -> 다음 칸으로 넘어가서 계속 반복!

    jnz L_NotFound                       ; [결과 판독] Jump if Not Zero (ZF = 0일 때 점프해라!)
                                         ; 해석: "끝까지 다 뒤졌는데도 끝내 같은 글자를 못 찾았구나(ZF=0)!"
                                         ; -> 못 찾았으니 L_NotFound 라벨로 점프!

L_Found:
    ; --- 여기는 '7'을 찾아서 ZF = 1이 된 경우에만 내려옵니다 ---
    ; (참고: 찾은 직후에도 EDI는 이미 다음 칸으로 +1 지나가 있으므로, 
    ;  나중에 찾은 위치가 필요할 땐 dec edi로 한 칸 뒤로 물려줍니다)
    mov edx, OFFSET msgFound             ; 성공 메시지 주소 준비
    call WriteString                     ; 화면에 출력
    call Crlf                            ; 엔터(줄바꿈)
    jmp L_Section3                       ; 실패 영역(L_NotFound)을 건너뛰고 다음 섹션으로 이동!

L_NotFound:
    ; --- 여기는 끝까지 못 찾아서 점프해 온 경우입니다 ---
    mov edx, OFFSET msgNotFound
    call WriteString
    call Crlf


    ; =========================================================================
    ; SECTION 3. Str_compare & Carry Flag (CF) : 두 문자열 사전순 크기 비교
    ; =========================================================================
L_Section3:
    ; Irvine32 라이브러리 함수로 두 문자열의 첫 글자부터 아스키 코드를 비교함
    INVOKE Str_compare, ADDR str1, ADDR str2
                                         ; 내부 계산: str1("Apple") - str2("Banana")
                                         ; 첫 글자 'A'(65) - 'B'(66) = -1
                                         ; 작은 수(65)에서 큰 수(66)를 뺄 때 모자라서 빌려옴(Borrow)!
                                         ; -> 빌림이 발생하면 CPU가 Carry Flag(CF)를 1로 올림! (CF = 1)

    jc  L_IsSmaller                      ; [조건 점프] Jump if Carry (CF = 1이면 점프해라!)
                                         ; 해석: "빌림이 발생했네? 앞 단어(str1)가 더 작구나!" -> 점프 성공!
    jmp L_Section4                       ; 만약 CF = 0이면(크거나 같으면) 그냥 다음 섹션으로 이동

L_IsSmaller:
    mov edx, OFFSET msgCompare           ; "str1이 str2보다 사전순으로 앞섭니다" 출력
    call WriteString
    call Crlf


    ; =========================================================================
    ; SECTION 4. DX:AX 16비트 나눗셈 구조 (105 ÷ 10 계산하기)
    ; =========================================================================
L_Section4:
    ; 💡 핵심 규칙: 어셈블리에서 16비트 나눗셈(div bx)을 할 때는
    ;    무조건 [DX : AX] 두 레지스터를 이어 붙인 32비트 공간을 피나눗수(분자)로 씁니다!

    mov dx, 0                            ; [상위 방 청소] DX에 쓰레기 값이 있으면 엄청 큰 수로 착각하므로
                                         ; 나눗셈 전에는 반드시 DX를 0으로 비워줘야 함! (필수 습관)

    mov ax, 105                          ; [나눌 수(분자)] 하위 방 AX에 105를 넣음 -> 결과적으로 [DX:AX] = 105

    mov bx, 10                           ; [나누는 수(분모)] 10으로 나누기 위해 BX에 10을 넣음
    
    div bx                               ; ★ 나눗셈 실행! ([DX:AX] ÷ BX)
                                         ; 약속된 결과 저장 위치:
                                         ;   - 몫 (10)     -> 무조건 AX에 들어감!
                                         ;   - 나머지 (5)  -> 무조건 DX에 들어감!

    ; --- 화면에 결과 예쁘게 출력하기 ---
    mov edx, OFFSET msgDivResult         ; "[3] 16비트 DIV 결과 : 105 / 10 = 몫 " 출력
    call WriteString
    
    ; Irvine32의 WriteDec는 무조건 32비트 레지스터인 'EAX'의 값만 출력할 수 있음!
    ; 그래서 16비트 AX(몫)를 32비트 EAX로 안전하게 옮겨 담아야 함
    movzx eax, ax                        ; Move with Zero-Extend: AX(10)를 EAX로 복사하고 앞의 빈자리는 0으로 채움
    call WriteDec                        ; EAX에 들어있는 몫(10)을 화면에 숫자로 출력!
    
    mov edx, OFFSET msgRemainder         ; ", 나머지 " 출력
    call WriteString
    
    movzx eax, dx                        ; 이번엔 나머지(5)가 들어있는 DX를 EAX로 복사 (앞자리는 0으로 채움)
    call WriteDec                        ; EAX에 들어있는 나머지(5)를 화면에 숫자로 출력!
    call Crlf                            ; 줄바꿈

    exit                                 ; 프로그램 정상 종료
main ENDP
END main
```
