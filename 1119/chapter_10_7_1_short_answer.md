## 📌 시작 전 필수 기초 개념 가이드

문제를 풀기 전, 어셈블리어 코드에서 자주 헷갈리는 4가지 핵심 개념을 먼저 짚고 넘어가세요!

### 1. 구조체(STRUCT)와 변수(`rentals`, `March`)의 진짜 정체
어셈블리어의 `.data` 영역은 함수(동작)를 만드는 곳이 아니라, **메모리에 데이터 상자(변수)를 미리 만들어 두는 창고**입니다.
* **`RentalInvoice`, `MonthlyTemp`**: 붕어빵 **틀** (사용자 정의 데이터 타입)
* **`rentals`, `myRental`, `March`**: 틀로 찍어낸 실제 **붕어빵(변수 상자)** *(※ 함수가 아닙니다!)*

### 2. 빈 상자 vs 채워진 상자 선언과 작동 방식
구조체 변수를 만들 때 꺾쇠 `<>` 안에 값을 넣느냐 비우느냐에 따라 이후 `.code`에서의 사용법이 달라집니다.

```masm
; [1단계] 설계도(STRUCT) 정의
RentalInvoice STRUCT
    invoiceNum  BYTE 5 DUP(' ')   ; 영수증 번호 (5칸 빈칸)
    dailyPrice  WORD ?            ; 하루 대여료 (2바이트 숫자, 비어있음)
    daysRented  WORD ?            ; 대여 일수 (2바이트 숫자, 비어있음)
RentalInvoice ENDS

.data
; ① 빈 상자로 만들기: 설계도의 기본값(빈칸, ?) 그대로 자리만 잡아둠
rentals RentalInvoice <>          

; ② 채워진 상자로 만들기: 처음부터 값을 쏙쏙 넣어서 생성
myRental RentalInvoice <"A1001", 5000, 3>

.code
; ① 'rentals'는 비어있으므로 나중에 값을 채워 넣어야 함
mov rentals.dailyPrice, 5000      ; 비어있던 칸에 5000 저장
mov rentals.daysRented, 3         ; 비어있던 칸에 3 저장

; ② 'myRental'은 이미 값이 있으므로 바로 꺼내서 계산 가능
mov ax, myRental.dailyPrice       ; 이미 들어있는 5000을 바로 꺼내옴
```

### 3. 데이터 단위별 크기 및 주소 이동 비교 (`BYTE` ~ `QWORD`)
메모리에서 다음 데이터로 이동할 때 더하는 숫자(`[March + 4]` 등)는 **데이터 상자의 크기(바이트)**에 따라 결정됩니다. *(※ 앞에 `S`가 붙은 `SBYTE`, `SWORD`, `SDWORD`는 음수(-) 표현이 가능하다는 뜻일 뿐 크기는 똑같습니다.)*

| 키워드 | 뜻 (유래) | 크기 (바이트) | 비트 수 | 다음 칸 이동 보폭 | 실제 배열 예시 (`10, 20, 30`) |
| :--- | :--- | :---: | :---: | :---: | :--- |
| **`BYTE`** | Byte | **1 바이트** | 8 bit | `+ 1` | `[arr]`, `[arr + 1]`, `[arr + 2]` |
| **`WORD`** | Word | **2 바이트** | 16 bit | `+ 2` | `[arr]`, `[arr + 2]`, `[arr + 4]` |
| **`DWORD`** | **D**ouble Word | **4 바이트** | 32 bit | `+ 4` | `[March]`, `[March + 4]`, `[March + 8]` |
| **`QWORD`** | **Q**uad Word | **8 바이트** | 64 bit | `+ 8` | `[arr]`, `[arr + 8]`, `[arr + 16]` |

### 4. 리터럴(Literal)이란?
변수 상자에 담기지 않고 **소스 코드에 직접 적어 넣은 '값 그 자체'**를 말합니다.
* **예시:** `mov eax, 10`에서 **`10`**(숫자 리터럴), `BYTE "Hello"`에서 **`"Hello"`**(문자열 리터럴)
* **매크로 `!` 연산자와의 관계:** 매크로에서 `<` 나 `>`는 원래 값을 묶어주는 특수 기호로 쓰입니다. 만약 특수 기호가 아니라 **글자(리터럴) 그대로의 `<` 나 `>`** 를 전달하고 싶을 때 앞에 `!`를 붙여(`!<`, `!>`) 마법을 해제합니다.

## 📝 10.7.1 Short Answer 문제 및 해설

### 1. What is the purpose of the STRUCT directive?

* **한국어 번역:** `STRUCT` 지시어(Directive)의 목적은 무엇입니까?
* **정답:** 사용자 정의 데이터 타입(구조체)을 정의하여, 서로 다른 데이터 타입을 가질 수 있는 연관된 변수(필드)들을 하나의 논리적 단위로 묶기 위함입니다.
* **상세 풀이:**
  * C언어의 `struct`와 동일한 역할을 합니다.
  * `STRUCT` 지시어 자체는 실제 메모리를 할당하지 않으며, 데이터의 설계도(템플릿)만 정의합니다. 이후 정의된 구조체 이름을 타입처럼 사용하여 실제 변수(인스턴스)를 선언할 때 메모리가 할당됩니다.

> **💡 쉬운 용어 & 예시 돋보기**
> * **지시어(Directive):** CPU가 실행하는 명령어(`MOV`, `ADD` 등)가 아니라, 코드를 번역하는 프로그램(어셈블러)에게 내리는 "작업 지시사항"입니다.
> * **구조체(STRUCT) = 붕어빵 틀:** 학생 한 명의 정보를 저장하려면 `이름(문자)`, `학번(숫자)`, `학점(실수)`이 필요합니다. 이걸 따로따로 관리하면 헷갈리니 `Student`라는 하나의 큰 상자(틀)로 묶어두는 것입니다. 틀만 만들었을 때는 메모리(밀가루)를 쓰지 않고, 실제로 붕어빵(변수)을 찍어낼 때 메모리를 차지합니다.

### 2. Structure Declaration Validity (구조체 선언의 유효성 판별)

> **문제 원문:**
> Assume that the following structure has been defined:
> ```masm
> RentalInvoice STRUCT
>     invoiceNum BYTE 5 DUP(' ')
>     dailyPrice WORD ?
>     daysRented WORD ?
> RentalInvoice ENDS
> ```
> State whether or not each of the following declarations is valid:  
> (다음 구조체가 정의되어 있다고 가정할 때, 아래 각 선언이 유효한지(Valid) 아닌지(Invalid) 판별하시오.)

* **a. `rentals RentalInvoice <>`**
  * **판별:** **Valid (유효함)**
  * **풀이:** `[변수명] [구조체타입] <초기값>`이라는 올바른 문법을 따르고 있습니다. 꺾쇠 괄호 `<>` 안을 비워두면 구조체 정의 시 설정한 기본값을 그대로 사용합니다.

* **b. `RentalInvoice rentals <>`**
  * **판별:** **Invalid (유효하지 않음)**
  * **풀이:** 변수명과 구조체 타입의 순서가 바뀌었습니다. 어셈블리어에서는 항상 **변수 이름이 먼저** 오고 그 뒤에 구조체 타입이 와야 합니다.

* **c. `march RentalInvoice <'12345',10,0>`**
  * **판별:** **Valid (유효함)**
  * **풀이:** 변수명(`march`), 구조체 타입(`RentalInvoice`), 그리고 3개의 필드에 대응하는 3개의 초기값(`'12345'`, `10`, `0`)이 순서와 타입에 맞게 정확히 전달되었습니다.

* **d. `RentalInvoice <,10,0>`**
  * **판별:** **Valid (유효함)** *(※ 책의 정답 기준)*
  * **풀이:** 변수명이 생략된 익명(Anonymous) 구조체 변수 선언입니다. MASM에서는 레이블(변수명) 없이 메모리 공간만 할당하고 초기화하는 것이 허용됩니다.

* **e. `current RentalInvoice <,15,0,0>`**
  * **판별:** **Invalid (유효하지 않음)**
  * **풀이:** 초기값의 개수가 초과되었습니다. `RentalInvoice` 구조체는 총 3개의 칸만 가지고 있는데, 4개의 값을 넣으려고 했기 때문에 에러가 발생합니다.

> **💡 쉬운 용어 & 문법 돋보기**
> * **`5 DUP(' ')`:** `DUP`는 Duplicate(복제)의 약자입니다. 공백(`' '`) 1바이트를 5번 복제해서 5칸짜리 빈 문자열 공간을 만들라는 뜻입니다.
> * **`?` (물음표):** "지금은 초기값을 정하지 않았으니 메모리 공간만 비워둬!"라는 뜻입니다.
> * **`<>` (꺾쇠 괄호)의 비밀:** C언어에서 배열을 초기화할 때 `{1, 2, 3}`처럼 중괄호를 쓰듯, 어셈블리어에서 구조체 값을 채워 넣을 때는 반드시 `< >`를 사용합니다.
>   * `rentals RentalInvoice <>` $\rightarrow$ `rentals`라는 변수를 만드는데, 안의 내용은 기본값(`'     '`, `?`, `?`) 그대로 둬라!
>   * `RentalInvoice <,10,0>` $\rightarrow$ 쉼표(`,`) 앞을 비워두면 "첫 번째 칸은 기본값(`'     '`)을 쓰고, 두 번째 칸엔 `10`, 세 번째 칸엔 `0`을 넣어라"라는 뜻입니다. (이름표가 없는 익명 메모리 공간)

### 3. (True/False): A macro cannot contain data definitions.

* **한국어 번역:** (참/거짓): 매크로(Macro)는 데이터 정의를 포함할 수 없다.
* **정답:** **False (거짓)**
* **상세 풀이:**
  * 매크로 내부에는 실행 코드(명령어)뿐만 아니라 데이터 정의(`BYTE`, `WORD`, `DWORD` 등)도 자유롭게 포함할 수 있습니다.

> **💡 쉬운 용어 & 예시 돋보기**
> * **매크로(Macro) = 자동 복사/붙여넣기(상용구):** 자주 쓰는 코드 뭉치에 이름을 붙여두고, 필요할 때마다 그 이름만 부르면 어셈블러가 그 자리에 코드를 통째로 복사해서 붙여넣어 주는 기능입니다.
> * **예시:** 화면에 인사말을 출력하는 매크로 안에 메시지 문자열(`msg BYTE "Hello!", 0`) 같은 데이터 정의를 함께 넣어둘 수 있습니다.

### 4. What is the purpose of the LOCAL directive?

* **한국어 번역:** `LOCAL` 지시어의 목적은 무엇입니까?
* **정답:** 매크로 정의 내부에서만 유효한 지역 레이블(또는 지역 변수명)을 선언하기 위함입니다.
* **상세 풀이:**
  * 매크로를 2번 이상 호출하면 내부의 레이블 이름이 중복 생성되어 에러가 발생합니다. `LOCAL` 지시어를 사용하면 어셈블러가 매크로를 복사할 때마다 고유한 임시 이름으로 자동 변경해 줍니다.

> **💡 쉬운 용어 & 예시 돋보기**
> * **왜 에러가 날까? (이름 중복 문제):**
>   만약 `MakeZero`라는 매크로 안에 `myData DWORD 0`이라는 변수가 있다고 합시다. 코드에서 `MakeZero`를 두 번 부르면, 똑같은 `myData`라는 변수가 두 개 생겨버려서 컴퓨터가 *"어느 `myData`를 말하는 거야?!"*라며 에러(중복 정의)를 냅니다.
> * **`LOCAL`의 해결 방법:**
>   매크로 맨 위에 `LOCAL myData`라고 적어두면, 어셈블러가 첫 번째 호출 때는 `??0000`으로, 두 번째 호출 때는 `??0001`로 이름을 몰래 바꿔주어 충돌을 막아줍니다.

### 5. Which directive displays a message on the console during the assembly step?

* **한국어 번역:** 어셈블(Assembly) 단계 중에 콘솔 화면에 메시지를 출력하는 지시어는 무엇입니까?
* **정답:** **`ECHO`**
* **상세 풀이:**
  * 프로그램이 실행될 때가 아니라, 소스 코드를 기계어로 번역하는(어셈블) 도중에 개발자의 터미널 창에 안내 메시지를 띄우기 위해 사용합니다.

> **💡 쉬운 용어 & 예시 돋보기**
> * **어셈블 단계 vs 실행 단계:**
>   * **어셈블 단계:** 요리사가 레시피(소스 코드)를 보고 요리(실행 파일)를 만드는 과정입니다. 이때 요리사에게만 보이는 메모가 `ECHO`입니다. (완성된 프로그램의 사용자에게는 보이지 않습니다.)
>   * **예시:** 코드 중간에 `ECHO Building 32-bit version...`이라고 적어두면, 빌드(컴파일)할 때 검은색 콘솔 창에 해당 문구가 출력됩니다.

### 6. Which directive marks the end of a conditional block of statements?

* **한국어 번역:** 조건부 어셈블리(Conditional Assembly) 문장 블록의 끝을 표시하는 지시어는 무엇입니까?
* **정답:** **`ENDIF`**
* **상세 풀이:**
  * `IF`, `IFDEF` 등으로 시작하는 조건부 어셈블리 블록은 반드시 `ENDIF`로 닫아주어야 합니다.

> **💡 쉬운 용어 & 예시 돋보기**
> * **조건부 어셈블리:** "만약 특정 조건이 맞으면 이 코드도 함께 번역해서 프로그램에 포함시키고, 아니면 무시해!"라고 어셈블러에게 지시하는 기능입니다. (C언어의 `#if ... #endif`와 같습니다.)
> * **예시:**
>   ```masm
>   IF DEBUG_MODE EQ 1      ; 만약 디버그 모드가 1이라면
>       ECHO Debug Mode ON  ; 이 줄을 번역하고
>   ENDIF                   ; 조건문 끝! (괄호 닫기 역할)
>   ```

### 7. List all the relational operators that can be used in constant boolean expressions.

* **한국어 번역:** 상수 부울 표현식(Constant boolean expressions)에서 사용할 수 있는 모든 관계 연산자를 나열하시오.
* **정답:** **`LT`**, **`GT`**, **`EQ`**, **`NE`**, **`LE`**, **`GE`**
* **상세 풀이:** 어셈블리어의 `IF`문에서는 `<`, `>` 기호 대신 영어 약어를 사용합니다.

> **💡 쉬운 용어 & 암기 팁**
> * **왜 `<`, `>` 기호를 못 쓰나요?** 2번 문제에서 보셨듯이, 어셈블리어에서는 `<>` 기호를 이미 데이터 묶음(괄호) 용도로 쓰고 있기 때문에 헷갈리지 않으려고 영어 약어를 씁니다.
> * **영어 줄임말로 쉽게 외우기:**
>   * **`EQ`** = **Eq**ual (같다, `==`)
>   * **`NE`** = **N**ot **E**qual (같지 않다, `!=`)
>   * **`LT`** = **L**ess **T**han (~보다 작다, `<`)
>   * **`GT`** = **G**reater **T**han (~보다 크다, `>`)
>   * **`LE`** = **L**ess than or **E**qual (작거나 같다, `<=`)
>   * **`GE`** = **G**reater than or **E**qual (크거나 같다, `>=`)

### 8. What is the purpose of the `&` operator in a macro definition?

* **한국어 번역:** 매크로 정의에서 `&` (치환 연산자, Substitution operator)의 목적은 무엇입니까?
* **정답:** 매크로 매개변수(Parameter)의 이름을 다른 텍스트나 문자열, 기호와 결합(치환)할 수 있도록 경계를 구분해 줍니다.

> **💡 쉬운 용어 & 예시 돋보기**
> * **치환 연산자(`&`) = 접착제 겸 구분선:** 매크로에 전달된 값을 글자 중간이나 따옴표 안에 끼워 넣고 싶을 때 사용합니다.
> * **예시:** 매크로 입력값(`num`)을 받아서 `var1`, `var2` 같은 변수를 만들고 싶을 때:
>   * `varnum DWORD 0`이라고 쓰면 어셈블러는 `num`을 입력값이 아니라 그냥 영어 단어 `varnum`의 일부로 착각합니다.
>   * `var&num DWORD 0`처럼 `&`를 붙여주면 *"여기까지가 `var`이고, 뒤의 `num`을 입력받은 값으로 바꿔치기해!"*라고 알려주어 `num`이 `1`일 때 `var1 DWORD 0`으로 예쁘게 합쳐집니다.

### 9. What is the purpose of the `!` operator in a macro definition?

* **한국어 번역:** 매크로 정의에서 `!` (리터럴 문자 연산자, Literal-character operator)의 목적은 무엇입니까?
* **정답:** 연산자나 특수 기호가 본래의 매크로 문법적 의미로 해석되지 않고, 순수한 일반 문자(리터럴) 그대로 취급되도록 강제합니다.

> **💡 쉬운 용어 & 예시 돋보기**
> * **리터럴(Literal) = "있는 그대로의 글자":** 특수 기능을 가진 기호의 마법을 해제하는 부적입니다.
> * **예시:** 매크로에 `<` 기호를 글자 그대로 넘겨주고 싶은데, 그냥 `<`만 쓰면 어셈블러가 *"어? 꺾쇠 괄호가 열렸네?"*라고 문법 기호로 오해합니다.
>   * 이때 `!<`처럼 앞에 느낌표(`!`)를 붙여주면 어셈블러가 *"아, 이건 문법 기호가 아니라 그냥 부등호 그림 문자 하나구나!"*하고 순순히 글자 그대로 받아들입니다.

### 10. What is the purpose of the `%` operator in a macro definition?

* **한국어 번역:** 매크로 정의에서 `%` (확장 연산자, Expansion operator)의 목적은 무엇입니까?
* **정답:** 텍스트 매크로나 상수 수식(Constant expression)을 먼저 계산(평가)하여 그 결과값을 문자열(텍스트)로 변환합니다.

> **💡 쉬운 용어 & 예시 돋보기**
> * **확장 연산자(`%`) = 계산기 버튼(`=`):** 수식 그대로가 아니라 **계산이 끝난 결과값**이 필요할 때 사용합니다.
> * **예시:** 콘솔에 숫자를 출력하는 `ECHO` 지시어를 쓸 때 차이를 비교해 보세요.
>   * `ECHO 5 + 3` $\rightarrow$ 화면에 계산을 안 하고 `5 + 3`이라는 글자 그대로 출력됩니다.
>   * **`ECHO %(5 + 3)`** $\rightarrow$ `%`가 먼저 `5 + 3`을 계산해서 `8`로 바꾼 뒤 출력하므로, 화면에 `8`이 출력됩니다.
