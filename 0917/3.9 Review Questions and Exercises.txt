3.9 Review Questions and Exercises
3.9.1 Short Answer

1. Provide examples of three different instruction mnemonics.
(세 가지 서로 다른 명령어 약어(Instruction Mnemonic)의 예시를 제시하시오.)

MOV (데이터 복사/이동), ADD (더하기), SUB (빼기)


2. What is a calling convention, and how is it used in assembly language declarations?
(호출 규약(Calling Convention)이란 무엇이며, 어셈블리 언어 선언에서 어떻게 사용되나요?)

함수(프로시저)를 부를 때 "매개변수를 어떤 순서로 전달하고, 다 쓴 메모리는 누가 정리할지" 정해놓은 약속(규칙)입니다.

.model flat, stdcall처럼 프로그램의 모델 선언부에 명시하여 사용됩니다.



3. How do you reserve space for the stack in a program?
(프로그램에서 스택 공간을 어떻게 예약하나요?)

.stack 지시자를 사용합니다. (예: .stack 4096은 스택 영역으로 4,096바이트를 예약함)



4. Explain why the term assembler language is not quite correct.
(어셈블러 언어(Assembler language)'라는 표현이 엄밀히 말해 올바르지 않은 이유를 설명하시오)

어셈블러(Assembler)는 소스 코드를 기계어로 바꿔주는 번역 프로그램 이름이고, 언어 자체의 이름은 '어셈블리 언어'이기 때문입니다. (C 언어 컴파일러를 C 언어라 부르지 않는 것과 같아요.)


5. Explain the difference between big endian and little endian. Also, look up the origins of this
term on the Web.
(빅 엔디안(Big Endian)과 리틀 엔디안(Little Endian)의 차이점을 설명하고, 웹에서 이 용어의 유래를 찾아 설명하시오.)


숫자를 메모리에 저장하는 순서 방식입니다.

빅 엔디안: 사람이 글을 읽듯 앞쪽(큰 쪽)부터 순서대로 저장합니다.

리틀 엔디안: 뒤쪽(작은 쪽)부터 거꾸로 저장합니다. (x86 컴퓨터가 쓰는 방식)

유래: 소설 《걸리버 여행기》에서 계란을 큰 쪽(Big end)으로 깨냐, 작은 쪽(Little end)으로 깨냐로 싸운 유머스러운 이야기에서 따왔습니다.


6. Why might you use a symbolic constant rather than an integer literal in your code?
(코드에서 정수 리터럴 대신 기호 상수(Symbolic Constant)를 사용하는 이유는 무엇인가요?)

MAX_SIZE = 100 처럼 이름을 붙여 쓰면 코드 의미를 알아보기 쉽고, 나중에 숫자를 바꿀 때 정의된 한 곳만 수정하면 되기 때문입니다.

가독성이 좋아지고 유지보수가 쉬워진다

ADULT_AGE = 19,  코드 하나만 바꾸면 전체가 변경된다.

7. How is a source file different from a listing file?
(소스 파일(Source file)과 리스팅 파일(Listing file)은 어떻게 다른가요?)

소스 파일(.asm): 우리가 직접 작성한 원본 코드 파일.
리스팅 파일(.lst): 어셈블러가 번역하면서 만든 "소스코드 + 해당 기계어 번호 + 주소"가 적힌 결과보고서 파일.



8. How are data labels and code labels different?
(데이터 라벨(Data Label)과 코드 라벨(Code Label)은 어떻게 다른가요?)

데이터 라벨: 변수 이름이며 뒤에 콜론(:)을 붙이지 않습니다. (예: myNum DWORD 10)
코드 라벨: 이동할 위치(점프 타겟) 이름이며 뒤에 콜론(:)을 붙입니다. (예: target:)




9. (True/False): An identifier cannot begin with a numeric digit.
((True/False): 식별자(Identifier)는 숫자로 시작할 수 없다.)

참(True)



10. (True/False): A hexadecimal literal may be written as 0x3A.
((True/False): 16진수 리터럴은 0x3A 형식으로 작성할 수 있다.)

거짓 (False) (C언어와 달리 어셈블리(MASM)에서는 3Ah 또는 03Ah 처럼 뒤에 h를 붙입니다.)




11. (True/False): Assembly language directives execute at runtime.
((True/False): 어셈블리 언어 지시자(Directive)는 런타임에 실행된다.)

거짓 (False) (지시자는 실행 전, 어셈블러가 코드를 번역(컴파일)할 때만 사용됩니다.)

지시자(Directive): 번역할 때 어셈블러가 참고하는 "작업 지시서"이므로, 프로그램 실행 전(번역 단계)에만 작동합니다.




12. (True/False): Assembly language directives can be written in any combination of uppercase
and lowercase letters.
((True/False): 어셈블리 언어 지시자는 대소문자를 구분하지 않고 조합하여 작성할 수 있다.)

참(True)



13. Name the four basic parts of an assembly language instruction.
(어셈블리 언어 명령어의 4가지 기본 구성 요소를 제시하시오.)

라벨 명령어 피연산자(대상) ;주석



14. (True/False): MOV is an example of an instruction mnemonic.
((True/False): MOV는 명령어 약어(Instruction Mnemonic)의 예시이다.)

참(True)



15. (True/False): A code label is followed by a colon (:), but a data label does not end with a 
colon.
((True/False): 코드 라벨 뒤에는 콜론(:)이 붙지만, 데이터 라벨 뒤에는 콜론이 붙지 않는다.)

참 (True)



16. Show an example of a block comment.
(블록 주석(Block Comment)의 예시를 보여주시오.)

코드 스니펫

COMMENT !
여기 안에 있는 내용은
모두 주석 처리됩니다.
!




17. Why is it not a good idea to use numeric addresses when writing instructions that access 
variables?
(코드에 진짜 메모리 주소(숫자)를 직접 쓰면 안 되는 이유)

코드를 조금만 수정해도 메모리 위치가 싹 다 바뀌어서 프로그램이 고장 나기 때문입니다.


진짜 주소 사용: 작은 수정이나 실행 환경 변화에도 위치가 틀어져 프로그램이 100% 고장납니다.
변수 이름 사용: 주소가 바뀌더라도 컴파일러와 운영체제가 현재 위치를 자동으로 계산해서 안전하게 연결해 줍니다.




18. What type of argument must be passed to the ExitProcess procedure?
(ExitProcess(프로그램 종료) 함수에 전달하는 값)

정상 종료되었는지 알려주는 정수 숫자(보통 0)입니다.



19. Which directive ends a procedure?
(프로시저를 종료하는 지시자는 무엇인가요?)

ENDP



20. In 32-bit mode, what is the purpose of the identifier in the END directive?
(32비트 모드에서 END 지시자에 붙는 식별자(Identifier)의 목적은 무엇인가요?)

END 단독 사용: 코드의 끝만 알릴 뿐, 어디서부터 실행해야 하는지 알려주지 못합니다.

END main 사용: 코드의 끝을 알림과 동시에, 프로그램이 실행될 시작 위치(엔트리 포인트)를 정확히 지정해 줍니다.




21. What is the purpose of the PROTO directive?
(PROTO 지시자의 역할)

"나중에 이런 함수를 쓸 거니까 미리 알아둬" 하고 어셈블러에게 알려주는 함수 선언문입니다.



22. (True/False): An Object file is produced by the Linker.
((참/거짓) 목적 파일(.obj)은 링커(Linker)가 만든다.)

거짓 (False) (어셈블러가 만듭니다. 링커는 .exe 실행파일을 만듭니다.)



23. (True/False): A Listing file is produced by the Assembler.
((True/False): 리스팅 파일(Listing File, .lst)은 어셈블러에 의해 생성된다.)

참 (True)


24. (True/False): A link library is added to a program just before producing an Execut
able file.
((참/거짓) 링크 라이브러리는 실행파일(.exe)을 만들기 직전에 합쳐진다.)

참 (True)

컴파일 단계: 내 코드가 잘 작성되었는지 기계어(.obj)로 번역만 해둡니다.

링킹 단계: 실행파일(.exe)을 완성하기 직전에 미리 준비된 라이브러리(.lib)와 합치는 작업을 거치므로, 지문은 참(True)입니다.





25. Which data directive creates a 32-bit signed integer variable?
(32비트 부호 있는 정수 변수 지시자)

SDWORD

26. Which data directive creates a 16-bit signed integer variable?
(16비트 부호 있는 정수 변수 지시자)

SWORD

27. Which data directive creates a 64-bit unsigned integer variable?
(64비트 부호 없는 정수 변수 지시자)

QWORD

28. Which data directive creates an 8-bit signed integer variable?
(8비트 부호 있는 정수 변수 지시자)

SBYTE

29. Which data directive creates a 10-byte packed BCD variable?
(10바이트 BCD 변수 지시자)

TBYTE
